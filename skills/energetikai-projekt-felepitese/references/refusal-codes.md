# Refusal codes / Elutasítási kódok

Write-tool errors are JSON `{error, reason, opId?, field?, hint, editRevision?, retryable?}`.
`error` is the closed code, `reason` a finer code, `field` the input path to fix and `opId` the
operation. `not_found` is deliberately uniform: a foreign id and a missing id look the same.
Tell the user what happened in plain words; do not paste the raw JSON.

| `error`                    | Typical `reason`                                                                                                                      | What to do                                                                                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `invalid_input`            | `required`, `unknown_field`, `invalid_value`, `unknown_operation`                                                                     | Fix the named `field` of `opId`. If the value is the user's to give, ask.                                                                                   |
| `invalid_input`            | `erp_scope_required`                                                                                                                  | Ask whether the DHW unit is ErP-labelled (`in`, then `erpEtaS` or `epsHMV`), `out` or `unknown`.                                                            |
| `invalid_input`            | `project_target`, `project_create_not_first`, `duplicate_op_id`, `duplicate_local_ref`, `unresolved_ref`, `too_many_material_creates` | Restructure the plan per references/plan-rules.md.                                                                                                          |
| `invalid_input`            | `mu_or_vapour_tight`, `material_out_of_bounds`                                                                                        | Recheck the material values with the user; a physically impossible value is refused.                                                                        |
| `invalid_input`            | `product_incompatible`, `category_mismatch`                                                                                           | The product states another type or carrier, or another category. Match it, or let the user pick another product or drop `productId`.                        |
| `invalid_input`            | `unsupported_layer`, `derive_rejected`                                                                                                | This assembly cannot be changed here; the certifier edits it in the app.                                                                                    |
| `missing_input`            | —                                                                                                                                     | Ask the user for the missing value and preview again.                                                                                                       |
| `ambiguous_reference`      | `ambiguous_selection`, `attribute_conflict`                                                                                           | A value contradicts the selected product or would overwrite a user value. Drop one side, after asking.                                                      |
| `conflict`                 | `revision_mismatch`, `dependency_changed`, `plan_changed`, `concurrent_write`                                                         | The project or a referenced row changed. Re-read `get_project_edit_context` and preview again (`concurrent_write` marked `retryable`: retry the same call). |
| `approval_required`        | `not_approved`                                                                                                                        | The user has not approved yet. Send them to the `approvalUrl`; a chat "yes" is not approval.                                                                |
| `expired`                  | —                                                                                                                                     | The plan or its approval expired (about 15 minutes). Preview again and send the new link.                                                                   |
| `replay_rejected`          | —                                                                                                                                     | The plan was already applied under another key. Do not apply again; read the project to confirm.                                                            |
| `idempotency_conflict`     | —                                                                                                                                     | The key belongs to another plan. Use a new key for this plan.                                                                                               |
| `verification_failed`      | —                                                                                                                                     | Applied, but the read-back did not match. Retry with the **same** key.                                                                                      |
| `rate_limited`             | `creation_cap`                                                                                                                        | Too many calls, or the daily cap (10 new projects per connection, 30 per organisation, 50 new materials) is reached. Wait; tell the user.                   |
| `write_disabled`           | `write_policy_off`, `role_not_permitted`, `subscription_required`                                                                     | Project changes are off for the organisation, the role (only owner, admin, certifier) or the subscription. An owner or admin changes it in the app.         |
| `insufficient_scope`       | `scenarios_scope_required`                                                                                                            | The connection lacks a permission. The user reconnects with project modification selected.                                                                  |
| `reauthorization_required` | `consent_outdated`, `grant_revoked`                                                                                                   | The write policy changed or access was revoked. The user reconnects the connector.                                                                          |
| `not_editable`             | —                                                                                                                                     | The project status or a frozen assessment blocks edits. Resolve it in the app.                                                                              |
| `not_found`                | —                                                                                                                                     | The id does not exist in this organisation. List or search again; never guess an id.                                                                        |

Read tools (`list_projects`, `get_project_readiness`, `get_energy_summary`, `list_scenarios`,
`compare_scenarios`) refuse with `invalid_arguments`, `invalid_cursor`, `over_cap` (for example
more than 3 scenarios in one comparison) or `not_found`.
